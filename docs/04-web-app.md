# סוכן פגישות — אפליקציה וובית

Oct 22, 2026 · @Efi

## מטרה ועקרונות

האפליקציה הוובית היא המקום לראות הכל ולשלוט בהכל: תור האישורים, ההיסטוריה, ההגדרות ואנשי הקשר. ווטסאפ הוא הערוץ המהיר, והאפליקציה היא הערוץ המלא. המסמך הזה משלים את מסמך ה-use cases (תרחישים UC-A1 עד UC-A8) ואת מסמך הארכיטקטורה.

1. **קודם לטלפון.** רוב השימוש יהיה מהטלפון, בין פגישות. כל מסך נבנה קודם לרוחב של טלפון.
2. **אישור מהיר, אבל לא עיוור.** אישור רגיל הוא לחיצה אחת. מה שחריג — נמען חדש, בקשה לא שגרתית, תוכן מעבר לתיאום — מודגש לפני שהכפתור נלחץ. (E12, T12)
3. **תוכן ממייל הוא תמיד טקסט.** שום דבר שהגיע מבחוץ לא מוצג כ-HTML ולא רץ בדפדפן. (T19)
4. **סנכרון מלא עם ווטסאפ.** פעולה שאושרה בערוץ אחד נעלמת מיד מהשני.
5. **עברית מימין לשמאל, בלי בלגן.** טקסט באנגלית בתוך עברית — כתובות מייל, שמות חברות, שעות — מבודד כך שהכיוון לא נשבר.
6. **כל לחיצה נרשמת.** כל פעולה באפליקציה נכנסת להיסטוריה, עם הערוץ "אפליקציה".

## משתמשים והתחברות

- **התחברות:** רק עם חשבון Google (OpenID Connect), עם הרשאות זהות בלבד. אין סיסמאות במערכת. חיבור Gmail ו-Calendar הוא זרימה נפרדת, והטוקנים שלה מגיעים רק ל-Google Gateway — ה-API לא רואה אותם. (T16)
- **הצטרפות:** רק דרך קישור הזמנה חד-פעמי, עם תוקף, שקשור לכתובת מייל מסוימת. התחברות עם חשבון אחר נדחית. (T14)
- **תפקידים:** משתמש ומנהל מערכת. מנהל רואה את מסך ניהול המשתמשים, ולא רואה שום נתון של משתמש אחר.
- **סשן:** cookie מסוג HttpOnly, Secure ו-SameSite, עם תפוגה אחרי זמן ללא פעילות.
- **אימות מחדש לפעולות רגישות:** חזרה לפעולה אחרי עצירת חירום, שינוי קוד העצירה, שינוי אמצעי האימות, וניתוק חשבון Google — כולן דורשות התחברות מחדש עם Google, גם אם הסשן עדיין פעיל. (T11, T28)

## מפת מסכים

בטלפון — סרגל ניווט תחתון עם ארבעה מסכים עיקריים. בשאר המסכים מגיעים מתוך ההגדרות.

| מסך | נתיב | מה עושים בו | use case |
| --- | --- | --- | --- |
| התחברות והצטרפות | /login, /invite/:token | כניסה עם Google, קבלת הזמנה | UC-A1 |
| הגדרה ראשונית | /onboarding | חיבור Google, אימות מספר ווטסאפ, שעות עבודה, קוד עצירה, אמצעי אימות | UC-A1 |
| תור אישורים (בית) | / | פעולות ממתינות: אישור, עריכה, דחייה | UC-A2 |
| פרטי פעולה | /actions/:id | הטיוטה המלאה, המייל המקורי, ועריכה | UC-A2 |
| היסטוריה | /history | כל מה שהסוכן עשה ומי אישר | UC-A3 |
| סיכומים | /summary | פגישות שנקבעו, בקשות פתוחות, מיילים שהסוכן דילג עליהם, פעולות שפגו | UC-A4 |
| אנשי קשר | /contacts | שמות ייחודיים וכתובות מייל | UC-A8 |
| הגדרות | /settings | שעות עבודה, משך ברירת מחדל, שפה ושאר ההגדרות | UC-A5 |
| אבטחה | /settings/security | קוד עצירה, אמצעי אימות, חשבונות מחוברים, ניתוק ומחיקה | UC-A7 |
| ניהול משתמשים | /admin/users | הזמנה והסרה של משתמשים, למנהל בלבד | UC-A6 |

הסרגל התחתון: תור, היסטוריה, אנשי קשר, הגדרות. הסיכומים מוצגים בראש מסך התור.

## תור האישורים

המסך החשוב ביותר באפליקציה, ומסך הבית. כל פעולה ממתינה מוצגת ככרטיס, והכרטיס צריך לאפשר החלטה בלי לפתוח עוד מסך.

&#91;embedded content: דוגמה חזותית · תור האישורים בטלפון\]

הכרטיס העליון מראה פעולה מול צד שלישי שסומנה כחריגה; התחתון מראה פעולה שגרתית במצב מקופל.

**מה יש בכרטיס:**

- **סוג הפעולה ותוקף:** מה הסוכן רוצה לעשות, ועד מתי האישור תקף (סוף יום העבודה). (E7)
- **נמענים במלואם:** כתובת מייל מלאה, לא רק שם. נמען שלא היה ב-thread מקבל תגית "נמען חדש". (T5, E2, E10)
- **מועד מפורש:** תאריך מלא ושעות. כשהצד השני באזור זמן אחר — שני אזורי הזמן. (E3, E4)
- **איש הקשר:** השם הייחודי שנתת.
- **הטיוטה המלאה:** כולל שורת הגילוי שהמייל נשלח על ידי הסוכן. משפט שחורג מתיאום מועדים מסומן. (E5)
- **סיבת החריגה:** מופיעה רק כשיש כזו, במילים פשוטות. (T29)
- **שלושה כפתורים:** אשר, ערוך, דחה.

**התנהגות:**

- **אשר:** פעולה שגרתית — מאושרת מיד. פעולה חריגה — נפתח חלון של אימות נוסף לפני האישור.
- **ערוך:** בחירת מועד אחר מתוך חלונות פנויים, או שינוי הנוסח. אחרי עריכה השומר בודק שוב, ונוצרת פעולה חדשה שמחכה לאישור.
- **דחה:** הפעולה נעלמת ונרשמת בהיסטוריה. אפשר להוסיף סיבה קצרה, אבל לא חובה.
- **לחיצה על הכרטיס:** פותחת את מסך פרטי הפעולה, עם המייל המקורי כטקסט נקי.
- **סדר הכרטיסים:** מה שפג הכי מוקדם למעלה.

## שאר המסכים

**הגדרה ראשונית (onboarding)**

אשף קצר בצעדים, שאפשר לעצור באמצע ולחזור אליו:

1. חיבור חשבון Google — מסך שמסביר בדיוק אילו הרשאות מתבקשות ולמה, לפני ההפניה לגוגל. החזרה מגוגל מגיעה ל-Google Gateway, ומשם חזרה לאשף.
2. אימות מספר הווטסאפ — קוד חד-פעמי שנשלח מהסוכן.
3. שעות עבודה ושעת סיום יום העבודה.
4. קוד עצירת חירום — מוזן פעמיים, ולא מוצג שוב אחרי השמירה.
5. אמצעי אימות לבקשות חריגות.
6. סיכום, והסבר קצר איך מדברים עם הסוכן בווטסאפ.

**פרטי פעולה**

כל מה שבכרטיס, ובנוסף: המייל המקורי כטקסט נקי, שרשרת ההודעות ב-thread, וההסבר של הסוכן למה הוא הציע את מה שהציע. במצב עריכה — בחירת מועד מתוך רשימת חלונות פנויים, ועורך טקסט פשוט לנוסח.

**היסטוריה**

רשימה כרונולוגית: מה בוצע, למה, מי אישר, מאיזה ערוץ ומתי. סינון לפי סוג פעולה, ערוץ, איש קשר וטווח תאריכים. כולל שינויי הגדרות ואירועי אבטחה של המשתמש עצמו.

**סיכומים**

- פגישות שנקבעו השבוע.
- בקשות שממתינות לתשובה מהצד השני.
- פעולות שפגו אתמול, עם כפתור "החזר לתור".
- מיילים שהסוכן דילג עליהם — שולח, נושא וזמן בלבד, מ-7 הימים האחרונים — עם כפתור "זו הייתה בקשה לפגישה". הסימון הזה נשמר, ומשמש לשיפור חוקי הסינון. (E9)

**אנשי קשר**

רשימה עם שם ייחודי וכתובת מייל, חיפוש, ועריכה. אנשי קשר חדשים שממתינים לשם מופיעים בראש הרשימה. שינוי כתובת של איש קשר קיים נחשב בקשה חריגה. (T29)

**הגדרות**

כל ההגדרות מהטבלה במסמך ה-use cases. ליד כל הגדרה — מתי השתנתה ומאיזה ערוץ.

**אבטחה**

- שינוי קוד העצירה ואמצעי האימות (דורש התחברות מחדש).
- חשבונות מחוברים: Google ומספר הווטסאפ, עם סטטוס החיבור.
- סשנים פעילים, ואפשרות לנתק את כולם.
- ניתוק ומחיקה: מחיקה מלאה של כל הנתונים והטוקנים, עם אישור כפול. ביומן הפעולות נשארות רק רשומות אנונימיות, בלי תוכן, כתובות או שמות.

**ניהול משתמשים (מנהל בלבד)**

שליחת הזמנה לכתובת מייל, רשימת משתמשים וסטטוס שלהם, ביטול הזמנה, והסרת משתמש.

## מצבים מיוחדים

| מצב | מה המשתמש רואה |
| --- | --- |
| הפעולה אושרה בווטסאפ בזמן שהכרטיס פתוח | הכרטיס נעלם, והודעה קצרה: "אושר בווטסאפ" |
| הפעולה פגה בזמן שהכרטיס פתוח | הכפתורים ננעלים, והודעה: "הפעולה פגה. אפשר להחזיר אותה לתור" |
| המועד נתפס בין ההצעה לאישור | אחרי לחיצה על "אשר": "המועד כבר לא פנוי", והצעה לבחור מועד אחר (E1, E7) |
| הסוכן מושהה (עצירת חירום) | פס אדום קבוע בראש כל מסך, תור ריק, וכפתור "החזר לפעולה" שדורש התחברות מחדש |
| החיבור ל-Google פג או נותק | פס אזהרה בראש כל מסך, וכפתור לחיבור מחדש. במצב בדיקה זה יקרה כל 7 ימים (E13) |
| תקרת ההוצאה היומית הושגה | פס אזהרה: "הסוכן עצר לעיבוד מיילים חדשים עד מחר" (T24) |
| פעולה נכשלה בביצוע | הכרטיס חוזר לתור עם סימון "נכשל" וסיבה בשפה פשוטה. שום כשל לא נעלם בשקט (E13) |
| תור ריק | "אין כרגע פעולות שמחכות לך", וקישור לסיכום היומי |
| אין חיבור לרשת | הנתונים האחרונים מוצגים, והכפתורים ננעלים עד שהחיבור חוזר |

העדכונים מגיעים בזמן אמת דרך Server-Sent Events. כך ווטסאפ והאפליקציה תמיד מסונכרנים.

## אבטחה באפליקציה

| איום | הגנה באפליקציה |
| --- | --- |
| Stored XSS דרך תוכן מייל (T19) | כל תוכן חיצוני מוצג כטקסט בלבד — אף פעם לא דרך HTML גולמי. Content Security Policy קשוחה בלי inline scripts. בדיקה אוטומטית עם payloads של XSS בנושא, בשם השולח ובגוף המייל |
| קישורים בתוך מיילים | לא הופכים לקישורים לחיצים אוטומטית. כשמוצג קישור, הדומיין שלו מוצג בבירור |
| CSRF על אישור (T10) | cookie מסוג SameSite, ו-token ייעודי לכל פעולה שמשנה משהו |
| זיוף או שימוש חוזר באישור (T10) | האישור נשלח עם מזהה הפעולה וה-hash שלה. השרת דוחה אישור לפעולה של משתמש אחר, לפעולה שהשתנתה, או אישור שכבר נוצל |
| clickjacking | האפליקציה לא נטענת בתוך iframe של אתר אחר |
| גניבת סשן | HttpOnly ו-Secure, תפוגה אחרי זמן ללא פעילות, ואפשרות לנתק את כל הסשנים |
| ניחוש קוד עצירה או אימות (T28) | הגבלת ניסיונות בשרת, והתראה על כל ניסיון כושל |
| סודות בצד הלקוח | אין מפתחות API או טוקנים בקוד של הדפדפן. הכל עובר דרך ה-API |
| דליפה בין משתמשים (T13) | ה-API מחזיר רק נתונים של המשתמש המחובר. מסך המנהל מציג רק שמות וסטטוס |

## שפה, כיווניות ועיצוב

- **עברית ו-RTL כברירת מחדל.** ה-HTML מוגדר עם dir="rtl" ו-lang="he". אנגלית — כשפת ממשק נוספת, בהמשך.
- **בידוד טקסט באנגלית.** כתובות מייל, שמות חברות, שעות וכל טקסט שמגיע ממייל עטופים ב-bdi או ב-dir="auto". זה מונע את הבלגן של עברית ואנגלית באותה שורה — נקודות וסוגריים שקופצים לצד הלא נכון.
- **CSS עם מאפיינים לוגיים.** margin-inline-start במקום margin-left, וכן הלאה, כדי שאותו קוד יעבוד בשני הכיוונים.
- **תאריכים ושעות.** פורמט ישראלי: יום.חודש ושעון 24 שעות. אזור הזמן מוצג במפורש כשהוא שונה משעון ישראל. (E3)
- **טלפון קודם.** כפתורים בגודל נוח לאצבע, סרגל ניווט תחתון, ובלי טבלאות רחבות במסכים העיקריים.
- **נגישות.** ניגודיות מספקת, ניווט במקלדת, ותוויות לקוראי מסך.
- **עיצוב פשוט ונקי.** הדגשה רק למה שחשוב: הכפתור הראשי, תגית נמען חדש וסיבת חריגה. מצב כהה — בהמשך.

## API שהאפליקציה צריכה

נקודות קצה ב-API (FastAPI). זו רשימה ראשונית — ה-schema המלא ייווצר אוטומטית כ-OpenAPI.

| קבוצה | נקודת קצה | מה היא עושה |
| --- | --- | --- |
| התחברות | GET /auth/google/login, GET /auth/google/callback, POST /auth/logout | התחברות עם Google והתנתקות |
| הזמנות | GET /invites/:token | בדיקת הזמנה לפני התחברות |
| משתמש | GET /me | פרטי המשתמש, סטטוס (פעיל או מושהה) ומצב החיבורים |
| חיבורים | POST /integrations/google/connect, DELETE /integrations/google | חיבור וניתוק של Gmail והיומן. connect מחזיר כתובת הפניה לגוגל; ה-callback מגיע ל-Google Gateway ולא ל-API |
| ווטסאפ | POST /whatsapp/verify, POST /whatsapp/confirm | שליחת קוד אימות ואישורו |
| פעולות | GET /actions?status= | רשימת פעולות לפי סטטוס |
| פעולות | GET /actions/:id | פרטי פעולה מלאים |
| פעולות | POST /actions/:id/approve | אישור — עם ה-hash, ועם קוד אימות נוסף לבקשה חריגה |
| פעולות | POST /actions/:id/reject | דחייה, עם סיבה אופציונלית |
| פעולות | PATCH /actions/:id | עריכה. יוצרת פעולה חדשה שמחכה לאישור |
| פעולות | POST /actions/:id/requeue | החזרה לתור של פעולה שפגה |
| חלונות פנויים | GET /availability?from=&to= | חלונות פנויים לבחירה בעריכה |
| היסטוריה | GET /history | עם סינון ועימוד |
| סיכומים | GET /summary/daily | הסיכום היומי |
| מיילים שדולגו | GET /skipped-emails, POST /skipped-emails/:id/mark-request | רשימה, וסימון "זו הייתה בקשה" |
| אנשי קשר | GET /contacts, POST /contacts, PATCH /contacts/:id | ניהול אנשי קשר |
| הגדרות | GET /settings, PATCH /settings | קריאה ועדכון |
| אבטחה | PUT /security/kill-code, PUT /security/verification, POST /security/resume, DELETE /sessions | פעולות רגישות — כולן דורשות התחברות מחדש |
| מחיקה | DELETE /me | מחיקה מלאה של המשתמש והנתונים שלו |
| מנהל | POST /admin/invites, GET /admin/users, DELETE /admin/users/:id | ניהול משתמשים |
| זמן אמת | GET /events | Server-Sent Events: פעולה חדשה, אושרה, פגה, נכשלה, שינוי סטטוס |

## הערות למימוש

הנחיות ל-Claude Code, בהתאם להמלצות במסמך הארכיטקטורה (ADR-007).

- **סטאק:** React עם TypeScript, ו-Vite לבנייה.
- **טיפוסים משותפים:** ה-client ל-API נוצר אוטומטית מה-OpenAPI של FastAPI, כך שהטיפוסים בצד הלקוח תמיד תואמים לשרת.
- **ניהול נתונים מהשרת:** ספרייה כמו TanStack Query — מטמון, טעינה מחדש, ועדכון אחרי אירועי SSE.
- **עיצוב:** Tailwind עם מאפיינים לוגיים (ms, me, ps, pe) לתמיכה ב-RTL. ספריית רכיבים — רק אם היא תומכת ב-RTL כמו שצריך.
- **בדיקות:** בדיקות רכיבים, ובדיקות מקצה לקצה עם Playwright. חובה: בדיקת XSS עם תוכן זדוני במייל, ובדיקה שאישור כפול נדחה.
- **בלי localStorage לנתונים רגישים.** הסשן ב-cookie בלבד.
- **פריסה:** קבצים סטטיים שמוגשים מקונטיינר nginx, עם כותרות האבטחה (CSP, ומניעת טעינה ב-iframe).
